# Lessons Cleanup: Design

Status: draft for review · Date: 2026-11-02 · Related: [MVP Architecture](../../architecture.md), [Core Slice](2026-11-01-core-slice-design.md), [Bot](2026-11-01-bot-design.md)

## 1. Goal

`process_text.v3` (commit `ac1bed3`) turned the product into "corrected or translated text plus a few
English lessons". It has one behaviour and writes lessons only in English. The code, contract, schema
and docs still carry the previous design: modes, explanation language, per-change corrections and
the bot's rerun buttons. The project is pre-release and local databases can be recreated, so
nothing is kept for compatibility.

Done means: code, the `/v1` contract, the DB schema and all docs describe only the v3 flow, the
Alembic history is one fresh migration, and `make lint && make test` pass on a freshly migrated
database.

## 2. Scope

Removed everywhere (code, tests, contract, schema, docs):

- `Mode` (`minimal`, `natural`, `polished`), including the bot's rerun feature.
- `explanation_language`.
- The `correction` table and `CorrectionRow`.
- Prompts `process_text.v1.j2` and `process_text.v2.j2`.
- Migrations `0001_initial.py` (empty) and `0002_core_slice.py`.

Kept: `process_text.v3.j2` and `PROMPT_VERSION = "process_text.v3"`, the `Language` enum (the
response's `source_language`), the one-retry JSON validation, input limits, message splitting and
error handling.

Out of scope: new features (lesson language, retry button, per-user settings). If one comes back,
a new prompt version and migration add it again.

## 3. Contract (`packages/contracts`)

```python
class ProcessTextRequest(BaseModel):
    text: str  # 1..4096 code points, not blank, never stripped

class ProcessTextResponse(BaseModel):
    interaction_id: UUID
    source_language: Language  # en | uk | ru
    output_text: str
    explanations: list[str]    # English lessons; the prompt asks for at most 5, not validated
```

`Mode` is removed from the package. The enum parity test covers only `Language`.

## 4. API

Domain (`domain/text_processing.py`):

- `RewriteRequest` is removed. The port becomes `TextRewriter.rewrite(text: str) -> RewriteOutcome`.
- `Interaction(id, user_id, input_text, outcome)`.
- `ProcessedText(interaction_id, source_language, output_text, explanations)`.
- `Mode` is removed.

Use case `process_text(auth, text, rewriter, interactions)`: rewrite, save, return. Transport maps
`body.text` in and `ProcessedText` out.

`ProxyRewriter.rewrite(text)` renders `process_text.v3.j2` with no variables. The prompt stays a
Jinja template so later versions can add variables without changing how prompts are loaded.

## 5. Database and migrations

Models: `app_user`, `identity`, `interaction`. `interaction` loses `mode` and `explanation_language`.
`CorrectionRow` is deleted.

Migrations: both existing files are deleted and replaced by one `0001_initial.py`, autogenerated
(`alembic revision --autogenerate -m initial --rev-id 0001`) against an empty database and then
reviewed by hand. The `alembic check` test proves models and migration agree.

This is a one-off pre-release reset. The rule "never edit a migration that is on `main`" stays in
AGENTS.md and applies from here on. To recreate a local database: `docker compose down -v`, then
`make dev-db && make migrate`. The commit message says so.

## 6. Bot

- `handlers/rerun.py`, `rendering/keyboards.py` and their tests are deleted. So are the dispatcher's
  `in_flight` data and the texts `ALREADY_WORKING`, `ORIGINAL_GONE`, `TOO_OLD` and `rewriting()`.
- `process_and_reply` is folded into `on_text`. It sends `ProcessTextRequest(text=...)`, replies
  without a keyboard, and logs `text_processed` without `mode`.
- Reply headers: `Translated from Ukrainian` / `Translated from Russian` for translations,
  `Lessons` for English with lessons, none for English without lessons.
- `/start` and `/help` text loses the paragraph about modes.

## 7. Docs

- `architecture.md` and `AGENTS.md` describe only the current flow: the scope bullet, components,
  sequence diagram, data table, `app_user` settings, the enum parity example and the bot's shared
  objects.
- The 2026-11-01 Core slice and Bot specs and plans are rewritten to the current design. Sections
  on the diff engine, reconciliation, corrections, categories, modes, explanation language and
  rerun are replaced with the v3 equivalents or removed. Project-structure docs get only the small
  fixes they need.

## 8. Testing

Tests are changed before the code (TDD):

- Contracts: the request has only `text`; the response round-trips `explanations`; `Mode` is gone.
- API unit: the use case takes text; `ProxyRewriter` sends the v3 prompt as the system message and
  the text as the user message; the parity test covers `Language`.
- API integration: the HTTP round trip with only `text`; the repository saves `interaction` without
  the removed columns; `alembic check` passes on the new migration.
- Bot: the text handler sends `{"text": ...}` and replies without a keyboard; routing has no
  callback route; reply headers have no mode.

Final check: `make lint && make test`, and a grep for `Mode`, `explanation_language`, `ChangeItem`,
`Category`, `reconcile`, `correction`, `rerun`, `in_flight`, `minimal` and `polished` over code and
docs finds nothing related to the old design (pydantic's `model_dump(mode="json")` is unrelated).
