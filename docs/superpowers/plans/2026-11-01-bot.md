# Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private Telegram chat with the bot improves or translates text through `POST /v1/texts/process`, shows short English lessons drawn from the edits, splits long replies, and survives slow LLM calls and API errors.

**Architecture:** Thin aiogram handlers over pure rendering functions. `ApiClient` gains `process_text` and reaches handlers through dispatcher workflow data. The bot keeps no state. `main.build_dispatcher()` wires routers, filters and the errors handler, and tests drive it with `Dispatcher.feed_update` and a recording Telegram session.

**Tech Stack:** Python 3.14, aiogram 3.31 (`aiogram.utils.formatting`, `ChatActionSender`), httpx2, pydantic 2, structlog, pytest + pytest-asyncio.

**Spec:** [docs/superpowers/specs/2026-11-01-bot-design.md](../specs/2026-11-01-bot-design.md). Read it alongside this plan; section references (§N) point there.

## Global Constraints

- No new runtime dependencies, no contract (`engleks_contracts`) changes, no Compose, Dockerfile or CI changes.
- `engleks_bot` never imports `engleks_api`. `api_client.py` is the only module that talks HTTP.
- Messages are built with `aiogram.utils.formatting` and sent with `**text.as_kwargs()` (text + entities, `parse_mode=None`). Never a parse mode, never escaping.
- Telegram limit: 4096 UTF-16 code units of visible text per message.
- `BOT_PROCESS_TIMEOUT_S = 130` for `process_text`; `health()` keeps the 10 s client default.
- The request is exactly `ProcessTextRequest(text=...)`; replies carry no keyboard.
- Logs carry ids, lengths and counts only, never the user's text or the model's output. Log events and fields exactly as §8. `log = structlog.stdlib.get_logger()` at module level.
- Routers handle private chats only.
- Work on branch `feat/bot`. Run `make lint && make test` before each commit.

## Review Focus

1. **The model's output contains markup** (`<b>x</b>`, `*bold*`, `_x_`, `[a](b)`). It must arrive verbatim, with `parse_mode=None`, never as formatting or a Telegram "can't parse entities" error. Pinned in Task 3 and Task 4.
2. **The user deletes the original while the text is processing.** The billed result must still be delivered, not lost to "message to be replied not found": every reply uses `allow_sending_without_reply=True`. Pinned in Task 4.
3. **A user taps a button on a reply sent by an older version of the bot** (`rerun:minimal`). There is no callback handler: no API call, no error, nothing sent. Pinned in Task 5.
4. **Exceptions and log lines echo the user's text.** A pydantic `ValidationError` on a blank text, or any exception in `update_failed`, must not put text into logs: the validation path logs nothing, and `update_failed` logs only `update_id` and `error_type`, no `exc_info`. Pinned in Task 4 and Task 5.

## Notes on the spec

- **Router factories.** aiogram raises `RuntimeError("Router is already attached ...")` when a module-level router is included twice, and the routing tests build many dispatchers. Each handler module exposes `build_router() -> Router`; handlers stay module-level functions. The private-chat filter sits on the dispatcher's root `message` observer, which gates every sub-router.
- **Real aiogram objects in handler tests (§9).** `Message.answer()` returns a `TelegramMethod` awaited through the bound bot, and `ChatActionSender` needs a real bot, so `AsyncMock(spec=Message)` does not work. Handler tests build real `Message` objects bound to a `Bot` on `RecordingSession` (the fixture §9 already requires).
- **Replies use `original.answer(..., reply_parameters=original.as_reply_parameters(allow_sending_without_reply=True))`** instead of `reply_to_message_id`: same threading, but a deleted original no longer loses the result.
- **`error_text` matches on `code`** (§7). `status_code` only matters when it is `None`. A `502` whose body isn't an `ErrorResponse` (a reverse proxy's HTML) gets the generic message.
- **`/start` and `/help` send the same `HELP_TEXT`** (copy fixed in Task 4).

### Task 3: Reply rendering and packing

**Files:**
- Create: `apps/bot/src/engleks_bot/rendering/reply.py`
- Modify: `apps/bot/src/engleks_bot/rendering/split.py`
- Test: `apps/bot/tests/test_reply.py`, `apps/bot/tests/test_split.py`

**Interfaces:**
- Produces:
  - `utf16_len(text: str) -> int` in `split.py` (public; `split_message` uses it instead of the per-char `_units` sum where that reads cleaner, behaviour unchanged).
  - `render_reply(response: ProcessTextResponse) -> list[Text]`: the §6 layout, packed into messages of at most `TELEGRAM_LIMIT` visible UTF-16 units.

Layout, exact (`n` from 1):

| Block | Nodes |
|---|---|
| Output | `response.output_text` as plain text |
| Header, translation (`uk`/`ru`) | `Bold(f"Translated from {Ukrainian\|Russian}")` |
| Header, English with lessons | `Bold("Lessons")` |
| Header, English without lessons | none: minor fixes may go unexplained, so "no changes" would be a false claim |
| Lesson | `f"{n}. {lesson}"` |

Packing: blocks `[output, header?, *lessons]`; separator before the header is `"\n\n"`, before each lesson `"\n"`. Greedy: append `separator + block` to the current message while its visible length stays ≤ 4096; otherwise start a new message with the block (no leading separator). A block longer than 4096 alone flushes the current message and becomes `[Text(chunk) for chunk in split_message(plain_text_of_block)]`, each its own message; the next block starts a new message. Visible length is `utf16_len(node.render()[0])`.

  - `handlers/errors.py`: `async on_error(event: ErrorEvent) -> None` logs `update_failed` with `update_id=event.update.update_id`, `error_type=type(event.exception).__name__`, and nothing else (no `exc_info`). Returning `None` (not `UNHANDLED`) makes aiogram's `ErrorsMiddleware` swallow the exception.
  - `main.build_dispatcher(api: ApiClient) -> Dispatcher`: `dispatcher["api"] = api`; root filter `dispatcher.message.filter(F.chat.type == ChatType.PRIVATE)`; includes `start.build_router()` and `texts.build_router()` in that order; `dispatcher.errors.register(errors.on_error)`.
  - `run()` builds `ApiClient(..., process_timeout=settings.process_timeout_s)` and uses `build_dispatcher(client)`. `main.py`'s `log` becomes `structlog.stdlib.get_logger()`.

Updates are fed with `Update.model_validate({...}, context={"bot": bot})` and `await build_dispatcher(api).feed_update(bot, update)`.
