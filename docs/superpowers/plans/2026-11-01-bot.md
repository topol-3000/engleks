# Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private Telegram chat with the bot improves or translates text through `POST /v1/texts/process`, explains every change, re-runs the same text in another mode with one tap, splits long replies, and survives slow LLM calls and API errors.

**Architecture:** Thin aiogram handlers over pure rendering functions. `ApiClient` gains `process_text` and reaches handlers through dispatcher workflow data. Re-run state lives in the Telegram messages (the reply chain and the remaining buttons); a process-local in-flight set only guards against double taps. `main.build_dispatcher()` wires routers, filters and the errors handler, and tests drive it with `Dispatcher.feed_update` and a recording Telegram session.

**Tech Stack:** Python 3.14, aiogram 3.31 (`aiogram.utils.formatting`, `CallbackData`, `ChatActionSender`), httpx2, pydantic 2, structlog, pytest + pytest-asyncio.

**Spec:** [docs/superpowers/specs/2026-11-01-bot-design.md](../specs/2026-11-01-bot-design.md). Read it alongside this plan; section references (§N) point there.

## Global Constraints

- No new runtime dependencies, no contract (`engleks_contracts`) changes, no Compose, Dockerfile or CI changes.
- `engleks_bot` never imports `engleks_api`. `api_client.py` is the only module that talks HTTP.
- Messages are built with `aiogram.utils.formatting` and sent with `**text.as_kwargs()` (text + entities, `parse_mode=None`). Never a parse mode, never escaping.
- Telegram limit: 4096 UTF-16 code units of visible text per message.
- `BOT_PROCESS_TIMEOUT_S = 130` for `process_text`; `health()` keeps the 10 s client default.
- Explanation language is always `en`; plain text is always `minimal`.
- Logs carry ids, lengths and counts only, never the user's text or the model's output. Log events and fields exactly as §8. `log = structlog.stdlib.get_logger()` at module level.
- Routers handle private chats only.
- Work on branch `feat/bot`. Run `make lint && make test` before each commit.

## Review Focus

1. **The model's output contains markup** (`<b>x</b>`, `*bold*`, `_x_`, `[a](b)`). It must arrive verbatim, with `parse_mode=None`, never as formatting or a Telegram "can't parse entities" error. Pinned in Task 3 and Task 4.
2. **A second tap lands while the keyboard edit is still awaiting Telegram**, before any API call. It must still be ignored: the in-flight key is taken before the first `await`. Pinned in Task 5.
3. **The user deletes the original while a re-run is processing.** The billed result must still be delivered, not lost to "message to be replied not found": every reply uses `allow_sending_without_reply=True`. Pinned in Task 4.
4. **A Telegram call fails in the middle of a re-run** (the send raises `TelegramBadRequest`). The in-flight key must be released, so a later tap on the restored or remaining buttons works. Pinned in Task 5.
5. **Exceptions and log lines echo the user's text.** A pydantic `ValidationError` on a blank text, or any exception in `update_failed`, must not put text into logs: the validation path logs nothing, and `update_failed` logs only `update_id` and `error_type`, no `exc_info`. Pinned in Task 4 and Task 6.

## Notes on the spec

- **In-flight key taken first (§5 Re-run).** The spec lists "add the key" after removing the keyboard. aiogram handles updates as concurrent tasks, so a tap arriving during `edit_reply_markup` would pass the check. The handler adds the key right after the check, before any `await`; the rest of the order is unchanged.
- **In-flight set in workflow data.** `dispatcher["in_flight"] = set()`, received as a handler argument like `api`. Still process-local and lost on restart; each test gets a fresh one.
- **Router factories.** aiogram raises `RuntimeError("Router is already attached ...")` when a module-level router is included twice, and the routing tests build many dispatchers. Each handler module exposes `build_router() -> Router`; handlers stay module-level functions. The private-chat filter sits on the dispatcher's root `message` and `callback_query` observers, which gate every sub-router.
- **Real aiogram objects in handler tests (§9).** `Message.answer()` returns a `TelegramMethod` awaited through the bound bot, and `ChatActionSender` needs a real bot, so `AsyncMock(spec=Message)` does not work. Handler tests build real `Message`/`CallbackQuery` objects bound to a `Bot` on `RecordingSession` (the fixture §9 already requires).
- **Replies use `original.answer(..., reply_parameters=original.as_reply_parameters(allow_sending_without_reply=True))`** instead of `reply_to_message_id`: same threading, but a deleted original no longer loses the result.
- **`error_text` matches on `code`** (§7). `status_code` only matters when it is `None`. A `502` whose body isn't an `ErrorResponse` (a reverse proxy's HTML) gets the generic message.
- **`/start` and `/help` send the same `HELP_TEXT`** (copy fixed in Task 4).

### Task 3: Reply rendering and packing

**Files:**
- Create: `apps/bot/src/engleks_bot/rendering/reply.py`
- Modify: `apps/bot/src/engleks_bot/rendering/split.py`
- Test: `apps/bot/tests/test_reply.py`, `apps/bot/tests/test_split.py`

**Interfaces:**
- Produces:
  - `utf16_len(text: str) -> int` in `split.py` (public; `split_message` uses it instead of the per-char `_units` sum where that reads cleaner, behaviour unchanged).
  - `render_reply(response: ProcessTextResponse) -> list[Text]`: the §6 layout, packed into messages of at most `TELEGRAM_LIMIT` visible UTF-16 units.

Layout, exact (`n` from 1, `label = category.value.replace("_", " ")`, `·` is U+00B7, `→` U+2192):

| Block | Nodes |
|---|---|
| Output | `response.output_text` as plain text |
| Header, English with changes | `Bold(f"Changes · {mode}")` |
| Header, English, no changes | `Bold(f"No changes needed · {mode}")` |
| Header, translation (`uk`/`ru`), always | `Bold(f"Translated from {Ukrainian\|Russian} · {mode}")` |
| Edit | `f"{n}. "`, `Strikethrough(original)`, `f" → {replacement} · {label}"` |
| Insertion (`original == ""`) | `f"{n}. + {replacement} · {label}"` |
| Deletion (`replacement == ""`) | `f"{n}. "`, `Strikethrough(original)`, `f" removed · {label}"` |
| Translation item | as above but `original` is plain text, never `Strikethrough` |
| Explanation (not `None`) | appended to the item block: `f"\n   {explanation}"` |

Packing: blocks `[output, header, *items]`; separator before the header is `"\n\n"`, before each item `"\n"`. Greedy: append `separator + block` to the current message while its visible length stays ≤ 4096; otherwise start a new message with the block (no leading separator). A block longer than 4096 alone flushes the current message and becomes `[Text(chunk) for chunk in split_message(plain_text_of_block)]`, each its own message; the next block starts a new message. Visible length is `utf16_len(node.render()[0])`.

```python
def change(original, replacement, category=Category.GRAMMAR, explanation="Why."):
    return ChangeItem(original=original, replacement=replacement, category=category,
                      explanation=explanation, start=None, end=None)

def response(changes, *, output="I went.", mode=Mode.MINIMAL, lang=Language.EN):
    return ProcessTextResponse(interaction_id=UUID(int=1), source_language=lang, mode=mode,
                               output_text=output, changes=changes)

def kwargs(r):
    return [m.as_kwargs() for m in render_reply(r)]

def ents(kw):
    return [(e.type, e.offset, e.length) for e in kw["entities"]]

def test_edit():
    [kw] = kwargs(response([change("has went", "went", explanation="Past simple.")]))
    assert kw["text"] == "I went.\n\nChanges · minimal\n1. has went → went · grammar\n   Past simple."
    assert ents(kw) == [("bold", 9, 17), ("strikethrough", 30, 8)]
    assert kw["parse_mode"] is None

def test_insertion_deletion_no_explanation_and_label():
    [kw] = kwargs(response([change("", "the", Category.ARTICLES, None),
                            change("very", "", Category.WORD_CHOICE, None)], mode=Mode.NATURAL))
    assert kw["text"].endswith(
        "Changes · natural\n1. + the · articles\n2. very removed · word choice")
    assert ents(kw)[-1][0] == "strikethrough"   # only the deletion is struck
    assert len([e for e in ents(kw) if e[0] == "strikethrough"]) == 1

@pytest.mark.parametrize("lang,name", [(Language.UK, "Ukrainian"), (Language.RU, "Russian")])
def test_translation(lang, name):
    [kw] = kwargs(response([change("пішов", "went", Category.OTHER, None)], lang=lang))
    assert kw["text"] == f"I went.\n\nTranslated from {name} · minimal\n1. пішов → went · other"
    assert [e[0] for e in ents(kw)] == ["bold"]

def test_no_changes():
    [kw] = kwargs(response([], mode=Mode.POLISHED))
    assert kw["text"] == "I went.\n\nNo changes needed · polished"

def test_markup_in_output_is_verbatim():           # Review Focus 1
    out = "<b>hi</b> *a* _b_ [x](y)"
    [kw] = kwargs(response([change("*a*", "_b_")], output=out))
    assert kw["text"].startswith(out + "\n\n") and "1. *a* → _b_ · grammar" in kw["text"]
    assert kw["parse_mode"] is None

def test_strikethrough_offset_after_emoji():
    [kw] = kwargs(response([change("ok", "fine", explanation=None)], output="😀"))
    assert ("strikethrough", 25, 2) in ents(kw)     # 2 + 2 + 17 + 1 + 3 units

def test_packs_at_block_boundaries():
    texts = [kw["text"] for kw in kwargs(response([change("a", "b", explanation="x" * 100)],
                                                  output="a" * 4000))]
    assert texts == ["a" * 4000 + "\n\nChanges · minimal", "1. a → b · grammar\n   " + "x" * 100]

def test_every_message_within_limit_with_astral_chars():
    r = response([change("😀" * 20, "🙂" * 20, explanation="😀" * 50) for _ in range(80)],
                 output="😀" * 1500)

def test_oversized_output_split_into_plain_messages():
```

**Interfaces:**
- Consumes: `process_and_reply` (T4); `RerunCallback`, `keyboard_modes`, `ALREADY_WORKING`, `ORIGINAL_GONE`, `TOO_OLD`, `rewriting` (T2); fixtures (T4).
- Produces:
  - `type InFlight = set[tuple[int, int]]` (`(chat_id, original message_id)`).
  - `async rerun(callback: CallbackQuery, callback_data: RerunCallback, api: ApiClient, bot: Bot, in_flight: InFlight) -> None`, in this order:
    1. `reply = callback.message`; not a `Message` (`None` or `InaccessibleMessage`) → `callback.answer(TOO_OLD, show_alert=True)`, stop.
    2. `original = reply.reply_to_message`; `None` → `reply.edit_reply_markup(reply_markup=None)`, `callback.answer(ORIGINAL_GONE, show_alert=True)`, stop.
    3. Key in `in_flight` → log `rerun_duplicate_ignored` (`mode`), `callback.answer(ALREADY_WORKING)`, stop.
    4. `in_flight.add(key)` **before any further `await`**; everything below runs in `try`/`finally: in_flight.discard(key)`.
    5. `remaining = [m for m in keyboard_modes(reply.reply_markup) if m != mode]`; `reply.edit_reply_markup(reply_markup=None)`; `callback.answer(rewriting(mode))`; log `rerun_requested` (`mode`).
    6. `ok = await process_and_reply(original, mode, remaining, user_id=callback.from_user.id, api=api, bot=bot)`; `not ok` → `reply.edit_reply_markup(reply_markup=reply.reply_markup)` (the snapshot from the callback).
  - `build_router() -> Router` registering `rerun` on `RerunCallback.filter()`.

Test setup shared by the tests below: `original = make_message("I has went.", message_id=10)`; `reply = make_message("I went. …", message_id=11, from_bot=True, reply_to=original, reply_markup=rerun_keyboard([Mode.NATURAL, Mode.POLISHED]))`; a `make_callback(message, mode)` local helper builds `CallbackQuery.model_validate({"id": "cb", "from": {...id 1}, "chat_instance": "ci", "message": message, "data": RerunCallback(mode=mode).pack()}, context={"bot": bot})`.

  - `handlers/errors.py`: `async on_error(event: ErrorEvent) -> None` logs `update_failed` with `update_id=event.update.update_id`, `error_type=type(event.exception).__name__`, and nothing else (no `exc_info`). Updates are fed with `Update.model_validate({...}, context={"bot": bot})` and `await build_dispatcher(api).feed_update(bot, update)`.
